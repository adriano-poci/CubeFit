    Configuration¶

    This page lists configuration variables that are present in the supplied source snapshot. Some legacy variables are still set by wrappers even when their effect belongs to alternate/older solver paths; verify the implementation you actually import.

    HDF5 and generation¶

    Variable Purpose
    HDF5_USE_FILE_LOCKING HDF5 locking behavior used by manager/tracker code
    CUBEFIT_RDCC_NSLOTS HDF5 raw chunk-cache slot count
    CUBEFIT_RDCC_NBYTES HDF5 raw chunk-cache byte budget
    CUBEFIT_RDCC_W0 HDF5 chunk-cache preemption parameter
    CUBEFIT_GEN_PROCESSES HyperCube generation process count
    CUBEFIT_GEN_BLAS_THREADS BLAS threads used during HyperCube generation

    Streaming solver diagnostics/checkpointing¶

    Variable Purpose
    CUBEFIT_DIAG_LEVEL Diagnostic verbosity/emission level
    CUBEFIT_DIAG_STRIDE Diagnostic sampling stride
    CUBEFIT_DIAG_TOPK Number of top entries retained in selected diagnostics
    CUBEFIT_DIAG_JSONL JSONL diagnostics output path
    CUBEFIT_SOLVER_CHECKPOINT_EVERY Checkpoint cadence
    CUBEFIT_TRACKER_QSIZE Tracker writer queue capacity
    FITTRACKER_START Preferred multiprocessing start method for tracker

    Wrapper-configured scientific controls¶

    kz_run.py sets a larger family of CUBEFIT_* variables, including lambda/regularisation, orbit-prior, global-energy, and zero-column thresholds. These include CUBEFIT_LAMBDA_AGE, CUBEFIT_LAMBDA_ASMOOTH, CUBEFIT_LAMBDA_FLAT, CUBEFIT_LAMBDA_GROUP, CUBEFIT_LAMBDA_L1, CUBEFIT_LAMBDA_L2, CUBEFIT_ORBIT_BETA, CUBEFIT_ORBIT_PRIOR_WEIGHT, CUBEFIT_GLOBAL_ENERGY_BLEND, CUBEFIT_GLOBAL_TAU, and zero-column controls. Treat these as implementation-specific rather than a stable public configuration API unless the selected solver reads them directly.

    CPU/thread controls¶

    The code uses OMP_NUM_THREADS, OPENBLAS_NUM_THREADS, and MKL_NUM_THREADS to control nested numerical-library parallelism. CLI wrappers inspect SLURM_CPUS_PER_TASK. Avoid setting both a high process count and a high BLAS thread count without checking total CPU allocation; oversubscription can reduce throughput substantially.
