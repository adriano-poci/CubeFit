    Workflows¶

    1. Prepare an HDF5 file¶

    For programmatic setup, use H5Manager or populate_base_from_arrays() to persist LOSVDs, the observed data cube, templates, optional mask, and spectral grids. Use set_spectral_grids()/manager helpers to persist grids and build the rebinning artifacts required by the HyperCube builder.

    2. Validate the convolution path¶

    from CubeFit.hypercube_builder import assert_preflight_ok

assert_preflight_ok("galaxy.h5")

    For datasets with a suspected global velocity offset, estimate it before generation with estimate_global_velocity_bias_prebuild() and pass the resulting value as vel_bias_kms to build_hypercube().

    3. Build or resume the HyperCube¶

    from CubeFit.hypercube_builder import build_hypercube

build_hypercube(
    "galaxy.h5",
    norm_mode="model",
    amp_mode="sum",
    S_chunk=128,
    C_chunk=1,
    P_chunk=360,
)

    The _done bitmap makes repeated calls resumable. print_hypercube_done_status() and invalidate_done() in hdf5_manager.py support inspection and deliberate rebuilds.

    4. Fit¶

    Instantiate PipelineRunner only after the base datasets exist. Choose a warm-start mode deliberately: zeros for a new fit, saved_x to reuse only coefficients, or resume to restore solver state when possible.

    5. Reconstruct¶

    For a full stored model cube, use reconstruct_modelcube_fast() or reconstruct_modelcube_fast_parallel() from kz_fitSpec.py. For selected spaxels, reconstruct_model_spectrum() in hdf5_manager.py or plot_sparse_spectra_from_x() avoids generating a full /ModelCube.

    6. Diagnose¶

    Use plot_aperture_fit() for observed/model spectra, plot_white_light_images() for spatial summaries, plot_model_decomposition() for decomposition views, and plot_diagnostic_jsonl_dashboard() for solver JSONL diagnostics. compare_orbit_vs_solution_absolute() examines component/orbit constraint behavior.

    7. Validate with synthetic data¶

    validation.py can create a minimal validation cube from an existing model cube and compare the recovered solution with the generating solution. This is the preferred path for checking end-to-end recovery after solver or normalization changes.

    CLI wrappers¶

    kz_run.py wraps genCubeFit() for generation/fitting and accepts --galaxy, --run-switch, --ncomp, and redraw flags. kz_rio.py wraps loadCubeFit() for result loading/analysis. Both infer CPU availability from SLURM_CPUS_PER_TASK when present, with repository-specific fallbacks.
